## 2.2 技术解决方案

VO-AI 是独立开发的系统，并非基于 Coze、Dify 或任何其他智能体平台。我们选择自建，是因为
变更单管理有三项通用平台难以保证的要求：

**第一，金额必须可审计，AI 不能算钱。** 工料测量师必须能把 VO 报告中的每一个数字追溯到
具体的计量行和合同单价。因此所有金额都由确定性的计算引擎（规则引擎）计算，每次结果相同、
可以逐行检查。大型语言模型只负责理解问题、检索和解释合同条文；它引用的任何金额都必须来自
计算引擎的结果，否则服务器会拒绝显示该回答。

**第二，回答必须有合同依据。** 「问合同」功能只根据项目知识库中检索到的条文回答，每一点都
必须标明引用的条款号；服务器会逐条核对引用是否真的来自检索结果。找不到相关条文时，系统会
明确表示无法回答，而不是凭一般知识推测。

**第三，数据必须安全。** 合同、已计价的工程量清单及变更记录属于商业敏感资料。系统采用
账号登录、按项目和角色的访问控制，并把 AI 的 API 密钥只保存在服务器上。

### 技术架构

| 层级 | 实现方式 |
|---|---|
| 前端 | HTML5、CSS3、原生 JavaScript（ES2020），无框架、无构建步骤；支持电脑和手机，中英文界面。 |
| 后端 | Supabase（新加坡数据中心）：PostgreSQL 数据库、用户认证、文件存储、实时同步，以及 Edge Functions（服务器端函数）。 |
| 访问控制 | 每张数据表都启用行级安全（Row-Level Security）：用户只能看到自己被加入的项目；数据库还会按角色检查每一个字段，例如承包商不能改评估金额，业主不能改计量。新注册的账号在被顾问加入项目之前看不到任何资料。 |
| 计算引擎 | 确定性规则引擎（js/calc.js、js/analysis.js）：计量、单价与合同 BQ 交叉核对、新单价（Star rate）识别、差额与工期计算。 |
| 结构化知识库 | 合同条款规则表与工程元素表（js/clauses.js、js/elements.js），用于变更分类及受影响工程的提示。 |
| 向量知识库（RAG） | pgvector：PAM 2018 合同条文共 231 段，以 text-embedding-v4 向量化（1024 维），按语义相似度检索。 |
| AI 模型 | 通义千问（阿里云 DashScope）：qwen-plus 回答合同问题，qwen-flash 作备用；qwen-vl 对扫描版合同进行 OCR。 |
| AI 安全检查 | 服务器端逐条核对：① 必须引用至少一条检索到的条款；② 不得引用未检索到的条款；③ 回答中的金额必须来自计算引擎、问题或条文本身。不合格时重试一次，仍不合格则不显示。 |
| 地图 | Leaflet + OpenStreetMap 街道图 / Esri 卫星图：显示工地位置及带 GPS 的现场照片。 |
| 文件处理 | CSV / XLSX 工程量清单导入；pdf.js 读取 PDF；扫描版合同经 OCR 后存入知识库。 |
| 示范模式 | 不登录也能完整使用示范项目，数据只保存在本机浏览器；「问合同」通过受限的访客通道使用（每人每天 20 次、全站每天 300 次）。 |
| 测试 | Node.js 内置测试运行器，438 个自动化测试全部通过；另以 Playwright 进行浏览器端到端测试。 |
| 部署 | 前端以 GitHub Pages 静态托管；数据库和服务器函数在 Supabase。 |

### 智能体与角色

系统按四个角色提供四个智能体，共用同一份合同知识库，但提示词的立场和任务不同：

| 角色 | 智能体的任务 |
|---|---|
| 承包商工料测量师 | 提交前自查：申报是否有合同依据、还缺什么证据。 |
| 合约管理人（建筑师 / 工程师 / SO） | 确认变更是否有有效的书面指示（AI / EI / SO 指示），并决定是否核证评估金额。 |
| 顾问工料测量师 | 依照合同条文评估变更：适用条款、估价规则、单价是否合理。 |
| 业主 / 发展商 | 以简明方式说明变更原因、金额、工期影响及是否可以核证。 |

### 整体流程

承包商提交变更 → 合约管理人确认指示 → 顾问工料测量师评估 → 合约管理人核证 → 业主确认

每一步只有对应的角色可以编辑自己的字段，其他字段只读并注明原因。所有决定都由专业人员作出，
AI 只提供合同依据、核对结果和建议。

## 3.1 访问方式

项目访问链接：https://cytang1107.github.io/VO-AI/
源代码：https://github.com/CYtang1107/VO-AI

只需用电脑或手机上的浏览器打开链接，无需安装。系统界面提供中文和英文，切换按钮在登录页和侧边栏。

### 方式一：评审一键体验（推荐）

在登录页点击 **「评审一键体验 →」**，即可以顾问工料测量师的身份进入示范项目
**Cadangan Pembangunan ABC Residence**，无需账号或密码。示范项目包含已计价的工程量清单、
三个处于不同阶段的变更单、工地地图和现场照片，以及 PAM 2018 合同知识库，「问合同」也可以
直接使用（为保护 AI 用量，每位访客每天 20 次）。

示范模式的数据只保存在评审自己的浏览器中，可以随意修改；在 Projects 页面点击
**恢复演示数据**（Restore demo data）即可恢复原始示范数据。如需体验其他角色，点击侧边栏的
**切换角色 / 登出**（Switch role / sign out），在「演示（免登录）」页选择另一个角色重新进入。

### 方式二：示范账号（体验多人协作）

在登录页的「团队账号」页使用以下示范账号登录（密码见提交附件）。这些账号是同一个云端项目的
成员；在一个账号中提交或评估变更后，其他账号会实时看到更新。

| 角色 | 账号 | 主要功能 |
|---|---|---|
| 承包商工料测量师 | contractor@vo-ai.demo | 提出变更、拍照记录现场、输入计量、附上图纸并提交 |
| 合约管理人（建筑师 / 工程师 / SO） | administrator@vo-ai.demo | 确认指示或退回承包商；核证顾问的评估金额 |
| 顾问工料测量师 | consultant@vo-ai.demo | 创建项目、导入合同和 BQ、评估变更、管理成员 |
| 业主 / 发展商 | client@vo-ai.demo | 审查建议、确认最终金额、追踪所有变更 |

评审也可以在「团队账号」页自行注册新账号；新账号需由项目的顾问加入后才能看到项目资料，
这正是系统保护数据的方式。

### 开始使用只需四步

1. 打开链接，点击「评审一键体验 →」。
2. 在 Dashboard 查看待处理事项、逾期期限和工地地图。
3. 使用侧边栏在 Dashboard、VO Register、Documents、AI Analysis 和 VO Reports 之间切换。
4. 打开任何一个变更单，切换到「问合同」标签页提问，查看带条款引用的回答。

### 3.1.1 三个测试问题

**问题 1 — 「承包商声称踢脚线的单价为每米 RM 31.00。这个价格是否正确？」**
打开 VO-001 的计量表。系统将承包商的单价与已计价的合同 BQ 比较，显示合同项目 B/4.2 为每米
RM 22.00，合同单价具有约束力，申报单价高出 RM 9.00（40.9%）；以 168 米计算，仅这一项就
相差 RM 1,512.00。

**问题 2 — 「建筑师指示将砌块墙改为砖墙。还需要计量什么？」**
打开 AI Analysis 并输入该描述。系统识别受影响的工程元素为墙体，并提示确认墙面饰面、防潮层、
踢脚线及油漆是否也需重新计量，同时说明原因。系统不会断言这些项目已改变，而是提示测量师
检查。

**问题 3 — 「规格变更算不算变更？依据哪一条？」**
打开 VO-001，在「问合同」中输入该问题。系统从 PAM 2018 知识库中检索条文，回答规格变更属于
变更，并引用 **PAM 2018 第 11.1 条**（材料或货物的种类或标准的更改）；点击引用可查看条文原文
及相似度。可以接着问「变更的工程按什么规则估价？」，系统会引用第 11.6 条的估价规则。若问题
与合同无关，系统会明确表示找不到相关条文，而不会凭空作答。
